    <topic id="U6" title="3dTproject 'points left after censoring' abort crashes rest_conn">
      <summary>When censoring leaves fewer than 3dTproject's minimum retained frames (9 in AFNI 26.0.09), the simultaneous-backend DOF dry run aborts with '** FATAL ERROR: only N points left after censoring -- cannot continue (need at least M)'. The parser recognizes neither this nor any message other than the DOF line and the fixed-regressor abort, so it raises ToolExecutionError; rest_conn does not catch it, so the whole analysis fails, including usable runs. The orchestrator reproduced this on real ABCD data in 9 of 120 sessions (7.5%). On that data the points-left abort was emitted for runs with 0 retained frames even though the fixed-regressor count also exceeded the retained frames, establishing that 3dTproject evaluates the points-left condition first.</summary>
      <research>No literature research (engineering defect; mechanism confirmed in code and in the local AFNI binary). Proposal verification: 2 verified, 1 concerns (minor); concerns incorporated as additions (a)-(c) and the documentation note below.</research>
      <approaches>
        <approach id="A1" label="Parse abort as DOF &lt; 1, with invariant guards" feasibility="high" risk="low">
          <description>New parse branch for the points-left abort that sets a synthetic DOF guaranteed below 1, so the existing dof_below_1 exclusion path handles the run.</description>
          <pros>Reuses the existing exclusion, warning and ModelError paths; one run no longer fails the analysis; other unparseable output still fails loudly.</pros>
          <cons>The recorded DOF is not AFNI's (it omits the bandpass stopband-regressor count, which 3dTproject does not report before aborting), so it is an upper bound on the true DOF.</cons>
          <statistical_considerations>dof = n_uncensored - n_orts - (polort + 1). The branch fires only when n_uncensored is at most 8 (minimum 9); config validation gives n_orts at least 8 and polort + 1 at least 2, so dof is at most -2. The exclusion decision therefore matches what the true DOF would give.</statistical_considerations>
        </approach>
      </approaches>
      <decision status="decided" chosen="A1">In fmri_first_level_proc/nuisance.py rest_nuisance, simultaneous-backend dry-run parser: (1) Add a parse branch, independent of whether the stopband-regressor line is present, matching r'only (\d+) points left after censoring -- cannot continue \(need at least (\d+)\)' against the combined stdout and stderr; capture both numbers and do not hard-code the minimum. (2) On a match, raise GuardError if the captured point count differs from n_uncensored; otherwise set dof = n_uncensored - n_orts - (polort + 1) from the values already in scope. (3) Raise GuardError if that computed dof is 1 or more (protects the sign guarantee against any future relaxation of the config floors). (4) Otherwise the existing path applies unchanged: the run is excluded with reason dof_below_1 and a RUN_SKIPPED high-severity warning, remaining runs proceed, and the existing ModelError ('Every run has DOF &lt; 1') applies when every run is excluded. (5) In that branch the per_run_dof record carries n_stopband_regressors = None and n_stopband_regressors_null_reason = "dry_run_aborted_censoring"; the branch must assign both so the unconditional n_stopband_regressors assignment is never reached with n_stopband unbound; bandpass_dim and bandpass_dim_null_reason ("simultaneous_backend") are unchanged. (6) Every other unparseable dry-run output still raises ToolExecutionError. (7) Add GuardError to nuisance.py's import from .exceptions. (8) Real-AFNI tests in tests/test_nuisance.py, modeled on lines 469-530: two runs, one fully censored below the minimum (spiky motion) and one clean, where the first is excluded as dof_below_1, the second is in S_pre and the function returns; both runs fully censored, raising ModelError; and the aborted run's per_run_dof record carries the null reason. (9) Documentation (deferred with U5): the QC schema states that under n_stopband_regressors_null_reason "dry_run_aborted_censoring" the recorded dof is an upper bound on the true DOF.</decision>
    </topic>

The QC assembly at lines 991-992 reads failed_runs_record, which is empty in the concat path, so regression failures in concat mode appear in 'failed_runs' but not in 'excluded_runs'. Predates v4.0.0.</summary>
      <decision status="decided" chosen="unify by populating failed_runs_record from concat mode">After the concat-mode stage completes (after line 727, within the _concat_mode_stage function), propagate any entries from the local 'failed' list to the outer failed_runs_record. This is a one-line addition: for each entry in 'failed', append to the outer scope's failed_runs_record (which the closure can access). The QC assembly at line 991 then naturally includes them. No new test needed: the existing test_rest_conn_pipeline.py end-to-end tests exercise both modes, and the change is purely additive to the QC record (adds run_failed entries to excluded_runs that were already in failed_runs).</decision>
